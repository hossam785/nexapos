# NEXA POS — الاختبارات الدائمة

```bash
node tests/run.js                 # كل المجموعات
node tests/run.js sync loyalty    # المجموعات اللي مسارها فيه كلمة من دول
MGPOS_REAL_DB="$APPDATA/NEXA/mgpos.db" node tests/run.js real   # كمان على نسخة من قاعدة المحل
```

- كل مجموعة بتشتغل بـNode بتاع Electron (`better-sqlite3` مبني ليه)، على قواعد في مجلد مؤقت **برّه المشروع** بيتمسح لوحده في الآخر.
- قاعدة المحل الحقيقية **عمرها ما بتتفتح**: `real-store.test.js` بينسخها بس (`copyFileSync`)، وبيتأكد في الآخر إن حجمها ووقت تعديلها زي ما هم.
- اختبار السيرفر بيستخدم `pg-mem` متنزّل في `%TEMP%\nexa-test-deps` (مش في المشروع).
- آخر سطر في أي مجموعة لازم يكون `ALL n CHECKS PASSED` (الـrunner بيقراه).

| المجلد | بيختبر |
|---|---|
| `helpers/` | `harness.js` (تحميل جهاز، بيع، مزامنة بين جهازين زي الشبكة بالظبط، بصمة الحالة) و`ipc.js` (الـhandlers الحقيقية بـipcMain وهمي) |
| `sync/` | مسح السجل ونقل الحالة، والهجوم، وHTTP، و«آخر تعديل يكسب»، والفصل والرجوع، واسترجاع النسخة، ونسخة المحل الحقيقية |
| `loyalty/` | الولاء (حدود، مزامنة، ترقية المحلات القديمة، إعادة الضبط) والـIPC |
| `warehouse/` | الأذونات، والتحويل، والجرد، والدفعات، وأرقام كل جهاز |
| `server/` | سيرفر السحابة: التبليغ، والمزامنة، والاحتفاظ، ووكيل السحابة الحقيقي |

قبل الرفع النهائي: حسام هيقول «نضّف»، ووقتها يتقرر المجلد ده يفضل ولا يتشال.
